# 近戰／遠程武器祝福：繁中翻譯與機制說明規劃

[維護索引](../README.md)｜[天賦共用流程](../../../AI%20Prompt/Game-Info-Workflow.md)｜[祝福分類](../../../Game%20Info/releases/1.13.X/blessings/README.md)｜[翻譯表](../../../Referneces/Translation.md)

## 一、目標與範圍

沿用老兵天賦表的運作方式，產生玩家能理解的祝福效果、觸發條件、疊層、傷害／恢復／冷卻算例，以及獨立的原始碼依據。用詞採臺灣繁體中文。

依使用者確認，本規劃僅涵蓋近戰與遠程武器的祝福，不延伸為全部武器的攻擊動作、屬性條、傷害表或操作指南。以祝福為主要資料單位，提供「祝福→適用武器」「武器→可用祝福」雙向索引；武器名稱、系列、型號與適用範圍一起核對，武器索引資料夾使用正確繁中名稱；法杖及職業專用武器不得只因不使用一般彈藥就漏列。本規劃中的武器頁只顯示可用祝福與本武器差異；完整武器操作文件仍屬既有weapons分類。

本次交付是規劃；完整祝福清單、正式翻譯、等級數值與六個驗證樣本尚未完成。尚無正式內容，不預先建立祝福或武器索引的空文件。

## 四、正式資料的目錄與命名

完整祝福以名稱為主要單位，武器另外提供反向索引。近戰／遠程祝福目錄都是查詢入口，連到同一份祝福主頁；兩種武器共用的祝福不重複建立兩份主頁。

下方為有實際內容後的目標結構，本次不建立空殼：

~~~~text
Game Info/releases/1.13.X/
  blessings/
    README.md                           全部祝福索引
    SOURCE_INDEX.md                     全部祝福的來源查閱入口
    UNUSED_DEFINITIONS.md
    melee/
      README.md                         近戰祝福索引
    ranged/
      README.md                         遠程祝福索引
    entries/
      <核對過的繁中祝福名稱>/
        README.md                       完整效果、算例與武器差異
        SOURCE_INDEX.md
        TIER_VALUES.md                  各實作變體的等級數值
        WEAPON_COMPATIBILITY.md         此祝福的適用武器／型號
        LOCALIZATION_COMPARISON.md
        DAMAGE_PERCENTAGE_REVIEW.md
        <祝福實作定義識別碼>.md
    weapons/
      README.md                         依武器查祝福
      melee/
        README.md
        戰鬥斧/
          README.md                     此武器可用祝福清單
      ranged/
        README.md
        步兵自動槍/
          README.md
        雙鏈重型機槍/
          README.md
    data/
      BLESSING_WEAPON_MAP.json           雙向索引共用的對應資料
~~~~

- 祝福主頁、武器頁與目錄使用核對過的繁中名稱。祝福資料夾採繁中祝福名稱，武器資料夾採繁中武器名稱；內部識別碼放來源與對應資料，不作玩家看到的資料夾名稱。
- 「戰鬥斧」「步兵自動槍」「雙鏈重型機槍」已對照1.13.1本體繁中／英文名稱；上方只有武器索引的命名範例，並未宣稱它們已完成祝福清單。
- 同一祝福在多個武器上有不同數值、觸發條件、持續時間或可用等級時，仍集中在同一祝福主頁，按武器／實作變體分列。只有核對後確實相同的部分才共用。
- 不能只因中文同名就合併不同祝福。先確認英文名稱、語系鍵、物品及實作對應；若實際是不同祝福而中文同名，以核對過的可讀限定名稱區別，不附程式碼尾碼。
- 同一繁中武器名稱的型號共用武器頁；不同型號可用的祝福／等級不相同時逐一分列，不能把系列聯集當成每個型號都可用。
- 先查翻譯表，再用本體名稱、英文名稱、語系鍵及實際武器對應確認。詞表衝突或缺詞登錄待確認，不為建目錄臨時猜譯。
- 武器頁保留名稱、型號、祝福清單、該武器的主要效果及必要差異，連到祝福主頁的對應變體；完整公式、等級說明與勘誤只維護在祝福頁。
- 武器專長及固有屬性獨立辨識，不因程式識別碼也含trait就誤納為祝福。

### 雙向清單與共同對應資料

| 查詢入口 | 玩家看到的內容 |
|---|---|
| 祝福→武器 | 祝福主頁列出適用武器、型號、可用等級與效果差異，武器名稱可點選至該武器祝福清單 |
| 武器→祝福 | 武器頁列出該武器可用祝福，祝福名稱連至唯一主頁及相應變體；不同型號或等級限制明確保留 |
| 近戰／遠程→祝福 | 各類別列出適用祝福並連至同一主頁；同時適用兩類的祝福可出現在兩個索引，但只有一份完整說明 |

BLESSING_WEAPON_MAP.json只保存經核對的名稱、實體、對應關係與來源，作為兩個方向清單的共同基準，不放待辦狀態或操作歷程。Markdown清單依同一份關係資料同步，不能手動在兩邊各維護一套武器／祝福配對。

| 資料 | 必要欄位與用途 |
|---|---|
| 來源版本 | schema版本、實際遊戲版本、固定原始碼SHA、文本Build，以及必要的物品對應來源 |
| 祝福 | 穩定祝福識別碼、核對後中英文名稱、名稱／描述鍵、唯一主頁路徑 |
| 武器與型號 | 穩定武器及型號識別碼、核對後繁中名稱、近戰／遠程分類、武器頁路徑 |
| 實作變體 | 所屬祝福識別碼、實作定義識別碼、來源文件及祝福主頁中的變體錨點；等級數值連至該變體的TIER_VALUES段落 |
| 對應關係 | 武器、型號、祝福、實作變體、該型號已確認可用的等級及證據來源 |

名稱及實作識別碼要分開：一個祝福可有多個實作，一個實作可適用多個武器。可用等級按武器／型號對應記錄，不能只從某份Lua有四組值推定每把武器都可取得四級。

來源不足的關係留在AI-LOGS的待核清單，不放入已確認的玩家清單。來源子文件仍保存機制證據；共同對應檔不取代原始碼分析。

### 祝福跨武器差異的呈現

祝福主頁先列共通效果，再提供「適用武器與差異」表，欄位為「武器｜適用型號｜可用等級｜效果差異」。數值不同者連至該武器變體的等級表與算例；條件不同者另列條件，不能只用一個百分比範圍概括。

共通部分只有一份；個別武器必要的觸發、疊層、到期、冷卻與傷害例子在同一主頁依變體整理。武器頁只顯示該武器的摘要與入口，不複製整段祝福內容。

### Enhanced_descriptions的參考方式

已檢查下列模組，正式翻譯時沿用其分辨名稱、描述與武器差異的方式：

- [WEAPONS_Blessings_Perks.lua](../../../Warhammer%2040%2C000%20DARKTIDE/mods/Enhanced_descriptions/Main_Modules/WEAPONS_Blessings_Perks.lua)：武器專長與祝福分區，祝福再分近戰／遠程；各祝福以描述語系鍵整理，使用數值占位符、條件／持續時間／疊層、必要註解與換行。將這些表達方式轉成天賦表既有的Markdown條列及算例，不直接搬Lua色碼與字串拼接。
- 同名祝福跨武器的差異明列在該祝福下，不能只套單一最高等級數值。例如MOD將放血者按突擊鏈斧、突擊鏈鋸劍、重型開膛劍分列，奪顱者也另列重劍差異；這些先當核查線索，實際數值、觸發與適用範圍必須回查1.13.1公開原始碼。
- [NAMES_Talents_Blessings.lua](../../../Warhammer%2040%2C000%20DARKTIDE/mods/Enhanced_descriptions/Main_Modules/NAMES_Talents_Blessings.lua)：名稱與效果描述分開處理；核對繁中名稱時分清實際啟用的翻譯、註解中的舊名稱及本體名稱，不把註解當成目前已套用的翻譯。
- [NAMES_Enemies_Weapons.lua](../../../Warhammer%2040%2C000%20DARKTIDE/mods/Enhanced_descriptions/Main_Modules/NAMES_Enemies_Weapons.lua)：目前沒有完整繁中武器名稱表，也沒有可用來直接建立全部武器資料夾的繁中對照；因此武器命名仍需由翻譯表與本體名稱逐項核對。
- MOD名稱、描述、註解及占位符只作組織、措辭與待查線索，不能取代公開原始碼機制證據；MOD的繁中也不能直接當成未經描述MOD修改的遊戲原文。

## 五、玩家頁面與翻譯規則

祝福主頁保存完整效果、各實作變體、適用武器、等級與算例；武器README保存反向祝福清單。總目錄及武器清單保留圖示與可點選連結，不能只列名稱或程式識別碼。

- 目錄名稱儲存格沿用 `[繁中名稱](#章節錨點)<br>- English Name`；中文前放對應32×32圖示。
- 目錄主要效果使用 `<ul><li>效果</li></ul>`；每筆維持單一Markdown來源行，避免多行清單破壞表格。
- 分類依實際效果使用增傷、暴擊／弱點、順劈／控場、恢復／資源、機動／防護等；只呈現已有內容，不套用天賦的閃擊／光環／能力／鑰石分類。
- 正文標題採繁中名稱(English Name)，每項之間有清楚標題、空行及分隔線。粗體欄首採 `- **觸發方式**：正文`，相鄰長條列留空行。
- 正文依需要列「適用武器與型號」「運作方式」「等級數值」「疊層與刷新」「傷害／恢復／冷卻算例」「必要例外」「繁中原文勘誤」。沒有的效果不硬列。
- 等級表列來源確認的Ⅰ～Ⅳ或實際可用等級；不能假設每項都有四級、全部可取得，或數值必定線性增加。目錄若只顯示最高等級效果，必須明寫等級。
- 目錄及正文寫玩家可理解的觸發條件；事件名稱、程式判斷式、識別碼、物品欄位與核對狀態放來源子文件及AI-LOGS。
- 先使用既有翻譯表。缺詞新增於原本武器／近戰祝福／遠程祝福段落，標明原文、適用範圍及待使用者確認，不另建平行詞表。
- 詞表已有重複或衝突者先列待確認，例如Power Maul、Inspiring Barrage；本次規劃不擅自選其中一個或改動既有詞表。同名天賦與祝福也需保留對應範圍。

### 算例與常見問題

- 每個算例列明武器／型號、祝福等級、動作、敵人護甲與部位、距離、暴擊／弱點、其他天賦與祝福；只改待比較項目。沒有完整資料時使用假設算例，不宣稱實測或固定武器收益。
- 說清楚效果改的是最終傷害某階段、威力、弱點／暴擊額外部分、機率、攻速、裝填速度、資源上限或缺額。威力+10%不能直接寫成所有武器最終傷害+10%。
- 計算都用「前提 → 數值代入 → 結果與單位 → 玩家意義」。例如只有同一傷害階段加算且其餘倍率為1時，原有25%加成、祝福另加10%：`100 × 1.25 = 125`變成`100 × (1 + 25% + 10%) = 135`，新增收益`10 ÷ 125 = 8%`。這是格式例，不是任何祝福的已確認數值。
- 裝填速度與裝填時間必須追實際公式，不能把加速20%直接寫成時間減少20%；不同動畫階段是否受益另核。
- 核對多彈丸、多段攻擊、持續傷害、爆炸與連鎖效果是每次攻擊、每次命中、每個目標或每次擊殺計數；暴擊率與一發射擊中多枚投射物的判定分開。
- 近距離傷害不等於近戰傷害；手持武器、攻擊來源與擊殺來源分開核對。
- 核對層數是加算／乘算、滿層是否刷新、每層獨立到期或共用倒數，以及換武器、收起武器、裝填、蓄力、特殊攻擊、連段中斷是否保留。
- 彈藥補給分清備彈、彈匣、無消耗與憑空產生；韌性恢復分清最大值、目前值、缺額與上限。
- 至少對照一項相關天賦的相同結算階段；不同階段不相加，相同名稱不代表相同作用。同一祝福的完整收益不能把各分項相對增幅直接相加。

### 繁中原文勘誤

只把明確方向、對象、資源移轉、物理量／單位、時間操作或數值矛盾列錯誤。資訊不完整、未列公式或例外不算錯誤。

已確認的翻譯問題寫在唯一祝福主頁對應說明或變體下、詳細資料連結之前；武器頁連至該處，不複製勘誤；完整中英模板、格式參數、hash及證據保存在LOCALIZATION_COMPARISON與逐祝福來源文件。沒有錯誤不加勘誤區塊。模板占位符、靜態代入與實際遊戲顯示分開，版本或物品對應不明只列待核。
