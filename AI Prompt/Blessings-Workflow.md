# Darktide 武器祝福：分析、玩家說明與雙向查詢提示詞

- 參考[Game-Info-Workflow](Game-Info-Workflow.md)，針對武器祝福建立獨立流程。
- 複製下方提示詞並填寫執行參數，可用於指定祝福、既有文件修訂、分批續作或版本更新。

---

- 請依指定版本的Darktide公開原始碼，分析武器祝福並交付臺灣繁體中文的完整玩家說明、實際算例、原文比較與來源證據。
- 每個祝福保留一份獨立詳細頁，支援「祝福查武器」及「武器查祝福」。
- 玩家目錄的主要效果是摘要，完整正文必須實際建立且有明確入口。

## 執行參數

- 工作模式：【指定祝福分析／既有文案修訂／分批續作／版本更新】
- 目標版本：【例如Release1.13.1】
- 固定公開來源：【完整SHA；不能用浮動master代替】
- 本次清單與順序：【祝福名稱、實際trait ID、需核對的武器變體】
- 停止條件：【例如完成指定六項、雙向索引及驗收後，停止供人工確認】
- 交付Repository與工作樹：【實際路徑、既有工作樹名稱】
- 工作分支：【使用者指定的既有分支】
- 唯讀來源Repository：【Darktide-Source-Code實際路徑】
- 輸出目錄：【例如Game Info/releases/1.13.X/blessings/】
- 本體語系來源：【Steam Build、實際版本、擷取日期、既有RAW批次】
- MasterItems來源：【版本、快取日期及已知版本關聯】
- 舊版比較基準：【完整SHA；未指定則不做版本比較】
- 主控：【沿用使用者設定；本專案目前為GPT-6.1 Sol（gpt-6.1-sol）／xhigh】
- 協助代理：【沿用使用者設定；本專案目前為GPT-6 Luna（gpt-6-luna）／max】
- 圖片保存：【SyuanTsai/Media-Assets的Issue附件；沿用既有授權與Issue】

- 先從對話、Git、現存文件與AI-LOGS補齊已知參數。
- 必要資訊仍缺少時才詢問。
- 使用者已確認的工作樹、模型、附件及提交授權不重複索取。
- FASTER只有在工具實際支援且能確認設定時啟用。
- 未提供設定不得宣稱已啟用。
- 版本、範圍或停止條件以本次使用者指示為準。

## 一、接手與既有成果

1. 定位指定既有工作樹及分支，核對staged、unstaged、untracked，保留既有變更。
2. 使用者要求沿用時，不另建、搬移、清理工作樹或切換主要工作區。
3. 讀取適用Repository指示、既有祝福文件、[詞表](../Referneces/Translation.md)、[AI-LOGS README](../AI-LOGS/Game%20Info/README.md)與[INDEX](../AI-LOGS/Game%20Info/INDEX.json)，核對已完成Commit、剩餘清單及最新呈現規則。
4. 首次建立流程時，以既有老兵技能正文及來源、公式、原文比較作內容模板。
5. 祝福已有已驗收樣本時，沿用其結構。
6. 只讀本次需要的內容，不為樣板重新分析已完成技能。
7. 純文件分析與提示詞維護不啟動production code bootstrap，不修改MOD Lua、遊戲程式或無關天賦文件。
8. Enhanced_descriptions的WEAPONS_Blessings_Perks.lua、NAMES_Talents_Blessings.lua僅參考組織與呈現。
9. MOD、詞表及既有文件不能替代機制證據。
10. 原始附件或舊紀錄缺失時，保存可用資料與具體缺口。
11. 不宣稱讀過缺失內容，不重新開始已完成項目。

## 二、版本、名稱與唯一機制證據

- 唯一機制、數值及程式行為證據：[Aussiemon/Darktide-Source-Code](https://github.com/Aussiemon/Darktide-Source-Code)。
- Wiki、攻略、論壇、影片、其他Repository及模型記憶不作機制證據。
- 核實Release與完整公開SHA。
- 本機來源僅供閱讀，引用使用`git show <SHA>:<path>`核對固定Git物件。
- 來源Repository保持唯讀，不自行更新。
- 重要結論附完整SHA及精確行號的永久連結：`https://github.com/Aussiemon/Darktide-Source-Code/blob/<SHA>/<path>#L<起始>-L<結束>`。
- 只確認行號存在不足以證明結論，必須閱讀相應內容。
- 本體中英名稱與描述以實際項目loc key、同一資源及key/hash精確配對。
- 保存Build、版本、資源、語系及必要短引文。
- 完整RAW、固定字典與復原資料保持本機忽略。
- 區分原始占位模板、依格式參數重建的文字及實際遊戲畫面。
- 重建只能在來源文件標為重建，不當作遊戲內測試。
- MasterItems快取日期不等於Steam Build。
- 來源歸屬及後端欄位狀態集中記錄，不能由日期推定同版，也不把它們反覆寫進玩家說明。
- 詞表用於統一用詞。
- 核實本體繁中後補鍵與對應。
- 替代名稱鍵及既有譯名保留可追溯說明，不因英文同名任意合併。

## 三、最多三組平行，逐項驗收與Commit

- 依「單項蒐集 → 主控複核 → 玩家正文與來源 → 圖片／索引／驗收 → 本機Commit」完成每項；使用者已授權最多三組不同祝福平行蒐集與整理草稿。

- 每組有獨立祝福、變體範圍與草稿檔；主控依序寫入共享資料、索引及正式文件，完成該項驗收後建立獨立本機Commit。

- 一組完成Commit後才釋出該組名額；同時處理的祝福最多三項。
- 同一祝福本次指定的多武器變體屬於同一項。

- 協助代理只做唯讀搜尋、證據整理、原文比較與草稿。
- 正式文件、詞表、Issue附件、Git index與Commit由主控處理。
- 每次派工提供固定SHA、祝福及變體ID、來源範圍、詞表、唯一證據規則及待解問題。
- 主控直接核對本項完整tier、wrapper覆寫、觸發條件、實際武器接線、RAW與型號限制；共通機制可沿用已直接核實的固定SHA證據快取，不把代理摘要當證據。
- 主控優先驗收已準備完成的項目，不等待三組全部完成；每個Luna交付完整研究草稿、差異表、精確來源證據與待複核事項。
- 每個代理只寫各自獨占草稿與證據，不改共享索引、正式文件、圖片或Git。
- 保留正式頁同儕複核；已確認且未變動的內容不反覆啟動完整審查。
- 有誤時要求同項修正；其他已派工的組可繼續查證，未通過的項目不得混入其他祝福的Commit。

### 實際接入鏈

- 玩家UI武器／型號 → MasterItems項目、trait category及限制 → 武器模板實際匯入／引用 → trait等級覆寫 → Buff模板／繼承 → 執行類別與事件條件 → 傷害、順劈、韌性或彈藥共用結算。

- 每條關聯都核對實際引用。
- 僅找到相似名稱、format_values或共用Buff預設值，不足以認定當前武器效果。

### 每項必要核對

- 觸發來源、受益對象、持用條件、攻擊類型、命中／擊殺／弱點／暴擊條件及例外。
- 每級數值與單位、作用階段、加算／乘算、上限、首次生效與結算先後。
- 一次攻擊、每次揮擊、每發、每顆彈丸、多目標與射擊次數的計數單位。
- 疊層、滿層刷新、共同或獨立期限、移除、冷卻、重設及再次可用條件。
- 換目標、切出／切回、射空、免費射擊、重新裝填及中斷後是否保留。
- 彈匣與備彈、轉移與生成、最大韌性與缺額、單次恢復與每秒速率。
- 共用結算是否讀取該欄位。
- 繼承、覆寫及未啟用分支不能混成玩家能力。

- 只核對本次效果實際涉及的項目，不為無關機制建立空白章節。
- 核心效果缺證據時，保存缺口，不標為完成。
- 繼續處理範圍內可獨立完成的項目。

### 固定SHA共通機制證據快取

- 本安排依2026-10-03使用者效率指示，取代每個祝福重新全文閱讀共用機制的舊做法。
- 將已核對的共用Buff、命中事件、疊層、計時、結算與武器切換區塊集中保存於AI-LOGS；每筆列完整SHA、路徑、精確行號、內容SHA-256、結論與適用條件。
- 本次快取：[共通機制證據](../AI-LOGS/Game%20Info/releases/1.13.X/blessings/2026-10-03-COMMON_MECHANISM_CACHE.json)。
- 完整核對一次後，後續只檢查當前實作是否滿足適用條件；差異、疑點、新增條件或固定SHA改變時，才重讀受影響區塊並更新證據。
- 不因名稱、suffix或使用相同base template就直接推定行為相同；完整tier、wrapper覆寫、觸發、實際武器接線、RAW名稱／描述與型號限制每項都核對。
- 來源Git物件與RAW配對收據可在ignored區依SHA與內容雜湊快取；不得省略初次讀取、內容驗證或本項適用性核對。
- RAW靜態重建使用已驗證的base／tier查值、百分比轉換、prefix／suffix與數字精度快取；每項仍核對自己的完整formatter設定與值，不能直接把runtime值當作顯示文字。
- 正式產生前檢查config分類為實際武器的melee／ranged／mixed、效果欄位為字串、數值只含實際weapon ID、refs四欄、規則五欄及圖示身份；MasterItems的item kind=weapon_trait不能作武器分類。
- 產生中斷時精確續作同項尚未完成的步驟，保留已完成內容與無關變更；不重跑會重複新增關聯的步驟。
- 工具輸出只列當前需要的區塊、差異與結果，不輸出巨大JSON或全部歷史紀錄。

## 四、玩家理解、來源證據與AI-LOGS分工

| 內容 | 保存位置 |
|---|---|
| 玩家效果、操作條件、實際算例、適用武器、等級、必要例外及勘誤 | Game Info的祝福獨立正文與查詢頁 |
| 公開程式永久引用、事件／參數、實作變體、公式推導、原文規則比較與證據邊界 | Game Info的來源子文件 |
| 模型派工、進度、工具輸出、圖片下載／附件驗收、測試是否執行、Commit、剩餘清單及修訂歷程 | AI-LOGS/Game Info/ |
| 完整RAW、快取、大型逐筆清單、圖片暫存、render輸出與原始console紀錄 | 既有ignored來源批次或AI-LOGS/Game Info/local/ |

- Game Info包括公開程式證據，但不包括程式執行或協作工作紀錄。
- 來源子文件也不放本輪進度、模型、Commit表、工具輸出、附件上傳結果或私人資料。
- 歷史紀錄保留，修訂另建紀錄並同步AI-LOGS的README與INDEX。

## 五、獨立詳細頁與玩家用詞

- 玩家正文、算例與勘誤採條列式，一點只說明一件事。
- 長段落拆成觸發、效果、持續、例外等獨立條列；算例將前提、計算與結果分點呈現。
- 相鄰長條列之間保留空行，避免一個項目塞入多條規則。

- 每個祝福完整正文唯一，存於`entries/<繁中祝福名稱>/README.md`。
- 標題為`繁中名稱(English Name)`，下方72×72原圖及繁中alt。
- 來源與返回連結清楚可用。
- 開頭直接用完整條列說明效果，不只複製目錄摘要。
- 依需要分述觸發、數值、首次生效、層數、刷新、移除、切換、資源及例外，再放算例、適用武器與必要勘誤。
- 欄首採`- **觸發方式**：正文`，冒號在粗體外，相鄰長條列保留空行。
- 一點集中說明一件事。
- 事件名、參數、trait ID、hash及程式更新時序的證明放來源文件。
- 已核對的祝福等級直接寫「等級I–IV」，各級稱I級、II級、III級、IV級。
- 算例使用「IV級」，不用「第四組」。
- 玩家武器／等級表不寫「程式定義；可取得等級待確認」。
- 後端欄位與等級範圍分開記錄，缺後端位元時JSON仍保留null，不假造查詢結果。
- 已確認效果使用直敘句。
- 不要在玩家頁反覆加入「固定程式」「未實測」「尚待遊戲內核對」或快取歸屬說明。
- 驗證範圍集中在來源及AI-LOGS。
- 只有真正影響玩家操作且缺必要證據的事項，才具體說明其限制。
- 保留影響使用的條件與例外。
- 不為縮短文字刪除首次生效、切換、資源限制或百分比作用階段，也不堆疊與當前效果無關的否定句。

### 算例與百分比

- 每個公式均包含「假設 → 實際數值代入 → 結果與單位 → 玩家意義」，算例留在玩家正文，證明放來源子文件。

- 威力與最終傷害分開，追查威力如何參與傷害、踉蹌及順劈，不直接稱為等比例最終增傷。
- 弱點／爆擊加成作用於額外部分時，至少比較兩種額外部分占比及一個已有同階段加成案例，列整次命中前後值。
- 爆擊機率加算以「百分點」說明。
- 近距離與近戰、攻擊傷害與目標承傷分開。
- 彈藥算例列觸發當下的彈匣、容量、備彈與移入量。
- 恢復算例列最大值、目前值、缺額、倍率與上限。
- 涉及疊層／期限時列零層到首次受益、滿層、滿層刷新、中斷及再次觸發。
- 按實際計數單位，不把多目標當固定每發一次。
- 相對收益使用`(生效後−生效前)÷生效前`。
- 中間階段與完整結果分開，假設算例不冒充具名武器實測。

## 六、原文逐規則比較與勘誤

- 先依程式獨立產生玩家效果，再比較同版本本體原文與既有文件。
- 使用下表，每條保留實際位置及精確來源：

| 規則 | 本體／既有文件描述與位置 | 程式行為與檔案／方法／行號 | 比較結果 | 理由 |
|---|---|---|---|---|

- 比較結果限定：**一致／明確矛盾／文件未涵蓋／未找到對應實作證據／無法確認**。

- 條件、對象、資源方向、單位、時間或數值有明確矛盾，才在玩家頁增「遊戲描述勘誤」，短引問題文字並說明正確效果。
- 省略公式、冷卻、上限或特殊互動屬文件未涵蓋。
- 不當成誤譯。
- 沒有錯誤不建立空白勘誤段落。
- 英文協助辨識譯意，不能替代程式。
- 中英都與行為不同時，列文本／程式差異，不宣稱只有繁中錯誤。
- 占位模板重建及跨版本差異放來源文件。
- 尚未核實同版的行為差異不直接定性為玩家原文錯誤。

## 七、多武器變體與雙向索引

```text
Game Info/releases/<版本系列>/blessings/
  README.md
  SOURCE_INDEX.md
  UNUSED_DEFINITIONS.md
  melee/README.md
  ranged/README.md
  entries/<繁中祝福名稱>/
    README.md
    SOURCE_INDEX.md
    TIER_VALUES.md
    WEAPON_COMPATIBILITY.md
    LOCALIZATION_COMPARISON.md
    DAMAGE_PERCENTAGE_REVIEW.md
    <實際trait ID>.md
  weapons/
    README.md
    melee/<繁中武器名稱>/README.md
    ranged/<繁中武器名稱>/README.md
  data/BLESSING_WEAPON_MAP.json
```

- 同一名稱鍵的多武器實作保留各自trait ID、數值、條件及來源，正文按差異分述。
- 相同數值或機制集中在本祝福正文、等級表與來源說明；武器變體頁只列差異、識別、適用型號及來源連結，不複製共通正文或相同大型JSON。
- 引用只保留足以支持結論的精確範圍，不以引用數量作完成標準。
- 同名不同鍵不能只憑中文字串合併。
- 未核對變體留盤點，不套用已知武器效果。
- JSON維護祝福、武器、型號、變體及逐型號binding。
- 雙向索引使用同一關聯資料。
- 祝福頁查武器，武器頁查祝福並可連到該型號的實作來源，不從系列聯集推定每型號通用。
- 資料夾使用核實繁中名稱。
- 同系列小版本沿用`<主版號>.<次版號>.X`，不新增日期、小版本或latest副本。
- 來源實際版本與SHA明確記錄。
- 主／分類目錄欄位為「祝福｜主要效果｜分類」，武器頁為「祝福｜本武器主要效果｜分類」。
- 名稱欄先放32×32圖示，使用`[中文名稱](正文連結)<br>- English Name<br>[完整說明](同一正文連結)`。
- 主要效果使用`<ul><li>完整條件與效果</li></ul>`，每筆資料維持單一Markdown來源行。
- 每個「完整說明」必須指向唯一完整正文，不連到工作紀錄或僅含來源網址的空殼。
- 適用表為「武器｜適用型號｜等級｜效果差異」。
- 只有有實際內容的分類與武器建立頁面，不列未分析空頁湊數。

## 九、分層驗收、Commit與停止

- 本安排依2026-10-03使用者指示，明確取代原本每項反覆全面掃描的安排；完整玩家說明、來源正確性、圖片、正式頁同儕複核與獨立Commit要求維持。
- 一個祝福及本次核對變體為一個提交單位；不同祝福不得合併Commit。

### 每項Commit前

- 主控核對本次完整tier、wrapper、觸發與特殊攻擊、切換、算例、RAW勘誤、型號限制及實際接線；共通機制依證據快取確認適用性。
- 核對本次新增或受影響正文、來源、等級表、原文比較、變體頁、雙向索引、相對連結與錨點。
- 實際解析本次新增或受影響Markdown，確認表格、條列、空行、粗體、32／72圖示與「完整說明」入口。
- 檢查本次來源引用的固定SHA、精確範圍及內容；已驗證且未變的區塊沿用內容雜湊收據。
- 核對RAW同資源、key/hash配對；既有完整RAW雜湊未變時沿用配對證據，不重複輸出全文。
- 核對本項圖片的item.icon、實際Issue附件、公開下載、內容雜湊、尺寸及目視收據；未變的已驗收附件沿用，不重複下載或上傳。
- 全域唯一性、完整盤點分割與共享索引一致性仍逐項執行，確保沒有重複、漏失或跨型號誤綁。
- 精確暫存本項及必要索引、詞表、AI-LOGS；核對staged diff、非二進位與Git diff格式後建立本機Commit。

### 每輪三項完成後

- 一輪包含三個已驗收且已Commit的祝福項目；只完成研究或草稿不計數。
- 執行完整文件格式、連結與全部來源掃描，保留既有錯誤baseline並證明沒有新增錯誤。
- 驗證器或共通結構改動時，不等三項，立即完整掃描。
- 發現錯誤時立即擴大檢查受影響範圍；修正後才能繼續派工或驗收受影響項目。
- 完整連結掃描沿用共用工具：

```powershell
python scripts/game-info/validate_game_info.py --root "Game Info"
python scripts/game-info/validate_game_info.py --root "AI-LOGS/Game Info" --exclude-dir local
python scripts/game-info/validate_game_info.py --root "AI Prompt"
```

- 來源與Markdown完整掃描也記錄實際scope、檔數、錯誤及收據雜湊，不把聚焦檢查寫成全Repository通過。
- 全面掃描的回合、已Commit項目、基準及結果保存於AI-LOGS；大型工具輸出保持ignored。
- 最後不足三項的批次與全部工作完成前，仍執行一次完整掃描。

### Commit、回報與停止

- 沿用Repository適用雙語Conventional格式；不虛構Jira、工時或遊戲內測試。
- 不用git add .，不reset、stash、amend或rebase；共用流程／結構修正可獨立文件Commit。
- Commit後核對SHA、剩餘狀態及回合計數；不為補記SHA建立空提交。
- 進度以已驗收且已Commit成果計數，清楚區分研究中、待驗收與完成；新盤點補出變體時重新標示需補驗收，不把舊Commit等同新版全部完成。
- 玩家文件只保存遊戲知識；派工、模型、驗收、進度、Commit、執行與未做遊戲測試紀錄保存於AI-LOGS。
- 文案／導覽修正只檢查受影響內容與不變數值，不重做已確認機制或圖片。
- 批次結束保存剩餘名稱、變體、型號關聯、缺口及交集外定義；逐筆清單ignored，Git保存摘要、相對位置與雜湊。
- 只完成樣本不能宣稱全部完成；核心缺證據項目不得假稱完成。
- 達停止條件立即停止新增派工與分析；目前使用者範圍是全部祝福，沿用工作樹／分支／唯讀來源／固定SHA，不重做已驗收項目。
