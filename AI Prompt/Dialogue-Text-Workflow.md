# Darktide 中英字幕對話整理 可重用提示詞

複製下方提示詞並填寫執行參數，可用於整理官方事件、修訂字幕版面、續作指定範圍或核對新版本來源。本流程獨立負責 DIALOGUE／劇情對話的來源、字幕配對、角色頭像、聊天頁、網站導覽及驗收。

[返回 Game Info 流程入口](Game-Info-Workflow.md)

---

請使用指定版本的 Darktide 公開 Source Code 與已核實同版本的遊戲語系資源，依官方事件逐檔整理英文及臺灣繁體中文字幕。正文唯一位置為 `Game Info/對話文本/`，每語言每事件只維護一份內容。以 LINE 式聊天氣泡呈現「官方頭像＋角色：字幕原文」，配色採 Darktide 風格的近黑、冷金屬灰與低亮度青藍點綴；兩語言使用完全相同的版型、事件檔名、順序與分支結構。

## 執行參數

- 工作模式：【首次整理／修訂現有版面／續作指定事件／核對新版本來源】
- 確切遊戲版本：【例如 Release 1.13.1】
- Steam Build：【例如 25606770】
- 公開原始碼：【Aussiemon/Darktide-Source-Code 的完整 commit SHA】
- 交付 Repository：【實際本機路徑】
- 唯讀 Source Code Repository：【實際本機路徑】
- 同版本語系來源：【既有本機來源批次或已核實的雲端封存】
- 語言：`en`、`zh-tw`。
- 本次事件清單及停止條件：【明列官方 event ID 或指定事件範圍】
- 對話文件唯一目錄：`Game Info/對話文本/`；不按版本建立正文或導覽副本。
- 舊版比較基準：【完整 SHA、版本及 Build；未指定則不做版本比較】
- 外部發布或 Git 授權：【依本次使用者明確指示；缺省只修改本機文件】

本輪範圍固定為 `debriefing_01` 至 `debriefing_10` 共 10 個事件，英文與繁中各 56 句；完成這 10 組後停止，不自行整理第 11 個事件。後續續作必須另有使用者指定的新事件清單及停止條件，仍使用同一對話目錄。

必要參數先從對話、現有文件及來源核實；無法確認才詢問。分支、模型、commit、push、PR、合併、下載或上傳方式的範例不構成本次授權，也不得宣稱使用了不可用的模型或工具。

## 一 開始前核對

1. 讀取適用 Repository 指示，核對工作路徑、目前分支與已有變更，保留使用者工作。純文件整理不自行啟動 production code 規劃或 bootstrap。
2. 完整讀取本提示詞，依 `AI Prompt/Game-Info-Workflow.md` 的流程分工確認本次對話範圍；字幕來源、目錄、版型及驗收以本流程為準。
3. 讀取 `Game Info/README.md`、`Game Info/對話文本/README.md`、至少一份中英正文、對應來源文件、角色表，以及 `AI-LOGS/Game Info/README.md` 和既有 `INDEX.json`。
4. 讀取 `Referneces/Translation.md`。官方角色與事件名稱以同版本 UI 語系為準；詞表只協助統一術語，不能取代官方原文與身分證據。
5. 盤點本次事件的中英原文、字幕 key／hash、voice profile、官方頭像、句數、順序與分支。沿用已確認內容，不能只建檔名及空標題。
6. 只修改本次對話文件、必要索引及紀錄。不要修改 MOD Lua、Source Code、歷史 RAW、固定字典、來源封存或雲端內容。
7. 不新增交付用字幕 JSON／JSONL 副本。來源批次的復原必要 JSON 與既有維護 `INDEX.json` 保留原用途；不得因交付不需要 JSON 而刪除歷史來源或管理資料。

## 二 唯一證據與版本固定

- 事件、觸發條件、說話者選擇、播放順序及分支：以指定公開版本的 `Aussiemon/Darktide-Source-Code` 為證據。
- 實際英文與繁中字幕、正式事件與角色名稱：以核實 Steam Build 的官方語系資源為證據。不能依程式鍵名稱補寫台詞，也不能從繁中反譯英文。
- 記錄確切遊戲版本、Steam Build、語系、資源與擷取日期，以及公開 commit 完整 SHA。擷取日期、提交日期與遊戲發布日期分開處理；不能根據今天日期宣稱版本最新。
- 本機引用必須核對與固定 Git 物件一致。未提交或無法核實的修改不能當成指定公開版本證據。
- 來源文件逐項使用固定 SHA 與行號的永久連結：`https://github.com/Aussiemon/Darktide-Source-Code/blob/<完整SHA>/<路徑>#L<起始行>-L<結束行>`。
- 中英字幕以同一資源、字幕 key／hash 配對；保留各語言的原始 entry_index。不能按跨語言行號、相近文字或排列順序猜配。
- 無法以 key 查找時，使用已驗證的遊戲 hash 演算法對應；保留碰撞或重複記錄，不覆寫歷史字典，也不只按文字去重。
- 若 Build 與原始碼尚未對上，在來源文件保留「待同版核對」，不宣稱已完成同版本驗證。
- 需要子代理時，僅委派唯讀搜尋、草稿與複核；主控仍須閱讀支持順序、角色及字幕配對的核心來源。

## 三 官方事件與對話重建

1. 一個官方事件對應兩份語言正文及一份共用來源 MD。以穩定 event ID 命名；正式事件名稱呈現在頁面與索引。
2. 固定影片依字幕陣列與 `subtitle_start` 核對順序，保留原始片段；不能為了接成自然句子而合併或補出不存在的片段。
3. 任務通訊或隊友對話追查 `define_rule`、`response`、`heard_speak`、voice profile 與實際音訊選擇機制，依前句及回應條件建立關係。
4. `sound_events` 可能是候選變體，不能一律視為逐句順序。隨機開場、角色回應及聲線變體分段列出，清楚標示條件與選項；不得拼成每次必然完整播放的假對話。
5. 沒有來源支持的前後關係不自行排序。不同事件即使文字相同也保留歸屬；同名任務的簡報、途中通訊及完成對話分開辨識。
6. A／B 戰役節點不能僅依名稱推定互斥、先後或每名玩家必經。由 backend 提供且未取得的解鎖拓樸不得補寫。
7. 這 10 組任務結束簡報各只有一位 NPC 發言。所有台詞忠實呈現該角色，不為了聊天感新增玩家回覆或交替左右分配說話者。
8. 未確定的事件名、角色、台詞或分支記錄缺口。已知官方繁中缺漏時不得自行補譯成官方字幕；另有翻譯授權才建立明確標示的譯稿。

## 四 統一的聊天字幕呈現

- 正文為可直接開啟的靜態 HTML；提示詞、語言索引、角色表、技術來源及工作紀錄採 MD。HTML 使用共用 `assets/chat.css`，不在每語言各維護一套樣式。
- LINE 感由頭像、角色名稱、氣泡形狀與訊息間距呈現；背景使用近黑，氣泡使用冷金屬灰，框線、導覽及必要重點使用低亮度青藍，避免大面積亮色或發光背景。字幕文字保持清楚對比，禁止沿用明亮藍白背景、白色氣泡或綠色按鈕配色。
- 一個事件一個聊天頁；同 event ID 的英文與繁中位於相同層級，檔名完全一致。
- 每句一則訊息：左側官方頭像，旁邊顯示該語系官方角色名與冒號，下方氣泡保存字幕原文。角色名、字幕與頭像均可見，不以 hash、首字母或文字圖示代替已取得的頭像。
- 所有台詞按真實說話者排列；本輪不捏造右側玩家訊息。只有來源支持的不同說話者才可以呈現另一側。
- 圖像保留原比例與內容；兩語言共用同一頭像與顯示尺寸。不裁切成另一個人、不改色、不以 AI 圖或粉絲圖代替。
- 保留原始大小寫、標點、停頓、換行、口語及附註。HTML 轉義只能處理格式安全，解析後的字幕文字必須與來源逐字一致。
- 所有 HTML 均逐層縮排與分行，包含 `index.html`、20 份事件頁的 `html`、`head`、`header`、`main`、`footer` 與每個訊息 `article`；巢狀層級使用一致的兩個空格，多個屬性逐行排列，讓每則訊息與屬性可清楚 diff。禁止將整頁、區塊或多則訊息壓成一行。
- `bubble` 的開啟標籤、整句原文及結束標籤保留在同一來源行；原文若本來含換行則原樣保留。不得為了縮排在 `bubble` 內加入換行或空格，也不得 trim 尾端空白。排版換行只放在標籤與訊息之間，不改變字幕文字節點。
- 共用 CSS 使用展開格式：選擇器、宣告與大括號清楚分行，每行一項屬性，`@media` 等區塊逐層縮排。禁止 minify 或將整份 CSS 壓成一行。
- 確認占位符與格式標記的用途後才作顯示處理；沒有替換依據，不猜填玩家名、物品或場景。
- 如顯示時間，只使用影片來源中的時間，不編造訊息發送日期、時間、已讀狀態或線上狀態。
- 頁首顯示官方事件名稱、語言切換及返回入口；頁尾提供來源與相鄰事件文件。兩語言的事件順序、訊息數、來源入口與導覽關係一致。
- 玩家正文不放 key、hash、Build 收據、模型分工、維護進度、提交紀錄或工具輸出；必要場景與劇情限制可保留。
- 對話頁本機離線可讀，不依賴遠端字體、即時 API 或外部腳本。縮小至手機寬度時，頭像、角色名、氣泡與字幕不重疊、不截斷。

- 對話導覽按「事件類型 → 官方事件 → 對話」分層。事件類型依 Source Code 的播放場景與範本歸屬確認；這 10 組皆屬任務結束簡報 / Mission debrief。各層使用可鍵盤操作的原生頁面連結，語言切換維持同一類型或事件。只列已整理的類型，不用任務名稱猜分類或加入空分類。事件順序沿用來源 metadata，以可見編號呈現，不猜測跨類型劇情時間線。

- 對話按「對話文本 → 語言 → 事件」存放。所有對話正文、語言索引、角色表及事件來源只維護這一份；版本、Build 與 Source Code SHA 記錄在 `source/<event ID>.md`，不另建立版本版型或副本。
- 英文目錄唯一為 `en/`；不保留舊「英文」目錄導覽、根目錄 10 個事件 MD 的重複入口或 ROUND_01 導覽。`Game Info/README.md` 直接連到本目錄索引。
- 搬移前建立可追溯快照與清單。先核對原文與引用，再移除已被新版取代的正文或重複導覽；既有完整資源、復原依據與雲端封存保持原位置及內容。
- 每份來源 MD 包含版本、SHA、Build、事件歸屬、播放或分支依據、角色與頭像對應、字幕 key／hash、中英 entry_index、時間序列及證據限制，並與中英正文雙向連結。
- SOURCE_INDEX 保留技術識別碼；閱讀頁與語言索引以官方事件名稱導覽。未完成項目與模型分工只記錄於 AI-LOGS。

## 六 頭像取得與保存

1. 優先核對 Source Code 的 `dialogue_speaker_voice_settings` 與同版本 UI 名稱，確認 voice profile、角色身分及 icon 資源。
2. 檢查本機是否已有可用官方圖像。只有材質路徑不代表圖片存在；需實際取得並檢查角色內容。
3. 本機遊戲擷取須唯讀，核對安裝 Build。DDS 解碼為 PNG 可保留原始內容，核對解碼前後像素，不重繪或改色。
4. 本機供閱讀的 PNG 保持 Git 忽略。發布前讀取 [Media-Assets 圖片保存規則](https://github.com/SyuanTsai/Media-Assets/blob/main/README.md)，經授權將角色頭像保存為 `SyuanTsai/Media-Assets` 的 Issue 附件，不將二進位圖片提交到分支。核對實際附件可匿名讀取、尺寸、大小及 SHA-256 與原圖一致；外部原圖網址不當成已保存的附件。
5. 取得日期、尺寸、檔案雜湊、解包工具與保存驗證留 AI-LOGS；玩家頁只呈現頭像與內容，來源頁保留角色映射。
6. 本機可讀不等於已上傳；未授權或未完成外部保存，不宣稱雲端附件完成。缺少頭像時保留已確認文案，記錄具體缺口，不以假圖冒充。

## 七 紀錄分離與驗收

1. 本輪範圍維持 10 個 event ID；英文及繁中各 10 頁、各 56 句；逐事件配對數量、順序及角色一致。核對所有正文只存在於 `Game Info/對話文本/`，沒有版本副本、舊英文入口、根目錄事件 MD 或 ROUND_01 導覽。
2. 對照官方來源逐句核對文字、key／hash、角色、順序與分支；檢查解析後的可見字幕，而非只搜尋檔案字串。
3. 直接檢查中英聊天頁與手機寬度：近黑／冷金屬灰／低亮度青藍配色、頭像載入、角色名完整、文字換行正常、無水平溢出，語言切換到同一事件。另核對所有 HTML 與 CSS 已展開、逐層縮排及分行；逐字核對 bubble 內容含尾端空白，未被格式化增刪換行或空格。
4. 核對 HTML／MD 相對連結、來源永久連結的 SHA 與行號，以及 Source Code Git 物件。依既有 `scripts/game-info/README.md` 執行引用檢查；本流程不自行增加 production code 測試。
5. 原始完整文本與雲端封存不更動；不要因資料已在雲端就刪除不可重建的本機原始來源。格式交付不另複製 JSON／JSONL 或完整文本。
6. 於 `AI-LOGS/Game Info/dialogues/<日期與唯一名稱>.md` 新增維護紀錄，記錄範圍、格式、來源、檢查結果、未解事項及停止點；保留歷史紀錄。沿用既有 INDEX.json 與 README 增加入口，不另按版本建立對話紀錄副本。
7. 本機快照、DDS、console 與預覽放 local/ 並忽略。可追蹤紀錄禁止私人絕對路徑、帳號名稱、Token、聯絡資訊；使用 Repository 相對路徑與 `<遊戲安裝目錄>`。
8. 未執行的檢查不能寫成通過；靜態核對不冒稱遊戲內逐場播放。圖像未上傳與來源未對齊等狀態如實記錄。
9. Git 操作只依本次明確授權；精確暫存相關文件，不使用 `git add .`，不自行 reset、stash、改寫歷史或推送。參考流程的提交範例不能擴大本次授權。
10. 完成本次指定事件即停止。最終提供聊天入口、中英索引、來源索引、提示詞與實際紀錄，不用原始 TXT 清單或盤點代替字幕對話交付。

## 八 續作與來源版本更新

- 續作先讀 `Game Info/對話文本/` 的事件與來源索引，以及既有維護紀錄，沿用正式名稱、頭像、深色共用版型與可 diff 的展開格式，再處理新的指定事件；不重複已完成範圍。
- 更新時重新固定公開 SHA 與同版 Build。比較新增／移除事件、字幕、角色、時間序列、觸發條件及候選變體；文字未改不代表播放行為未改。
- 不論同系列或跨系列來源更新，對話仍只維護 `Game Info/對話文本/` 這一份；更新事件來源文件的確切版本、Build、SHA 與差異依據，修訂紀錄放既有 AI-LOGS。原始完整資源批次與雲端封存保持原位置及內容，不產生對話版本副本。未核實來源時維持待核對，不把舊版驗收套用新版。

## 九 網站展示與發布

- 本 Repository 為對話、來源與維護紀錄的唯一編輯處；公開呈現使用 `SyuanTsai/SyuanTsai.github.io` 的 Darktide 資料區，沿用其既有 Jekyll 與 Pages 發布流程。
- 網站保存由已確認來源修訂產生的發布內容，記錄來源 SHA 與網址映射；不在兩邊各自手工改字幕，不另建立對話版本副本，也不匯出 AI-LOGS、提示詞或完整原始文本包。
- 頭像沿用本流程第六節的 Media-Assets Issue 附件，保留 Asset ID、SHA-256 與完整附件網址；角色已有有效附件可直接重用，不因跨 Repository 展示另存 Git 圖片。
- 網站依「事件類型入口 → 類型索引 → 每事件／語言獨立頁」呈現，正文不得集中到單一 HTML、JSON 或 YAML。入口及類型索引只保存名稱、角色、metadata 與閱讀連結；利用 Jekyll 依事件頁 metadata 產生清單。事件頁共用 layout／CSS，以普通連結切換語言、來源、前後事件，載入時只含該事件該語言的字幕；逐事件內容保持展開 HTML 與原文空白。新增事件只加入對應語言文件，不手工更新一個集中字幕檔。正式發布範圍以當次使用者指示為準。
- 網站入口、分類清單及對話頁的右上角各只有一個語言切換按鈕，直接連到同一頁的另一語言，不在每張卡片或正文列出兩個語言選項。分類卡的中英文名稱整體可點入目前語言正文；事件卡、閱讀標題及前後事件連結顯示同一組順序編號。清單共用 includes，配對與類型返回連結保持目前語言。
- 順序取自 `event_order`，這 10 組顯示 `01–10`；它表示已核實的簡報排列，不推論跨類型劇情時間線。繁中預設入口與英文入口各自有類型清單，標題連結、前後事件及返回分類皆維持目前語言；切換仍是同一分類或同一事件。
- 已確認配色：背景 `#030607`、面板 `#080d10`、冷金屬灰 `#0e1519`、氣泡 `#121b20`、框線 `#244048`、青藍重點 `#67b4c0`、次要青藍 `#55848d`、字幕 `#bac6ca`、次要文字 `#81979f`。保留官方頭像、角色、原始字幕時間與 LINE 式氣泡間距，全部 HTML／CSS 保持展開縮排。

網站 Repository 的展示結構如下；事件及語言正文各自分檔，類型依實際已整理內容擴充。

```text
darktide-preview.html                          繁中事件類型入口
darktide-preview/
├─ en/index.html                              英文事件類型入口
├─ mission-debrief/index.html                 繁中官方事件清單
├─ en/mission-debrief/index.html              英文官方事件清單
├─ en/mission-debrief/<event ID>.html         英文單事件正文
└─ zh-tw/mission-debrief/<event ID>.html      繁中單事件正文
_layouts/
├─ darktide-preview.html                     共用外框與右上角語言切換
└─ darktide-dialogue.html                    共用事件正文與前後導覽
_includes/
├─ darktide-category-list.html               自動產生目前語言的類型入口
└─ darktide-event-catalog.html               自動產生編號與可點標題
assets/
├─ css/darktide-preview.css                  共用深色聊天版型
└─ js/darktide-preview.js                    只在入口處理舊 hash 轉址
```

- 對話頁的 `event_id`、`event_order`、`event_type`、`locale` 與 `counterpart_url` 維持配對；入口、清單與正文共用版型，字幕只出現在自己的事件語言頁。目錄依 `site.pages` metadata 自動產生，新增事件只加入該事件的語言檔案。
- 網站修改後，驗證正式 Jekyll 產物中的單頁字幕、標題編號、語言與前後事件連結，以及入口／索引零字幕。以實際建置產物檢查桌面及 390px 手機，標題可用鍵盤進入，右上角語言按鈕只有一個，關閉 JavaScript 仍能閱讀與切換；逐句保留原文及尾端空白，不以來源檔大小冒稱實際建置大小。
- 版型確認、提交、Draft PR、合併及公開發布依當次授權與目標 Repository 規範辦理。建置及驗收證據保留於對話或網站交付紀錄；不將工作紀錄寫入玩家正文。
