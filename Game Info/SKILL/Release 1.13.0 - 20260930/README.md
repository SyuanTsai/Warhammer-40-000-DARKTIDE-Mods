## 方法與限制

報告面向繁體中文使用者：正文、介面說明與案例使用繁體中文名稱；技能標題保留詞表英文名；程式識別碼、語系鍵及逐行來源集中於來源子文件，不以 frag／krak／smoke 等縮寫代替中文手雷名稱。

從職業指定的當前 tree 追至 talent、ability／Buff／special rule，再追共用執行邏輯。重要結論使用完整 SHA 與行號的永久連結。原始碼確認、跨檔案程式推導及待確認事項分開標記。

MOD 僅參考依職業拆檔及排版；未用其機制、數值或譯名對照作證據。用詞沿用 `Referneces/Translation.md`；公開來源未核實官方繁體語系文字，因此文件中的中文與 key 對應不宣稱為官方名稱。新對應列為待使用者確認。

主控 Astra／xhigh 由使用者在本聊天確認；子代理以工具明確指定 GPT-6 Luna／max。子代理只提供唯讀草稿，正式結論由主控直接核對。靜態邊界案例不是遊戲內測試。

## 描述規則（本輪修訂）

- 玩家主文件的技能標題採「繁中名稱(English Name)」，不以程式識別碼當名稱。
- 主文件採遊戲技能描述，以精簡條列直接呈現效果；傷害、恢復、冷卻與疊層算例另列。協作紀錄、進度與名稱核對狀態不出現在玩家主頁。
- 有公式就代入實際數值，列出前提、計算過程、結果及單位。加算、乘算與上限必須用算例區分，不能只寫「增加幾個百分點」。
- 用「冷卻時間」「使用次數」「依序補回」等玩家能理解的用語。事件名、判斷式、資源池、底層計數及證據狀態留在來源子文件。
- 不呈現父子節點清單、「節點連線核對資料」或純粹描述連線與完成狀態的段落。確實影響玩法的能力升級、替換與互斥限制仍須用白話交代。
- 頁首提供可點選目錄；技能之間以分隔線區分，每節可返回目錄並開啟對應來源文件。
- 原先指定四欄「分類 | 繁中名稱 / talent ID | node ID | 狀態」保留在來源資料夾的技術索引；玩家目錄以名稱與主要效果協助查找。
- `TALENTS Veteran/` 每個技能一份來源 Markdown，保存語系鍵、實作呼叫、公式推導、固定版本永久連結及待確認事項。玩家主文件仍是一職業一份。
- 沿用五個樣本的描述規則，完成整個老兵；不修改標記模組或 MOD Lua。
