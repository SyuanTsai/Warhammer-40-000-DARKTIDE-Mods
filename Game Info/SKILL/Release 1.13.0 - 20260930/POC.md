## 冷卻代表：veteran_replenish_grenades

選擇原因：不同 ability 選用不同補給週期、缺額才開始計時、滿額重設、嚴格時間比較，並牽涉共用能力資源上限。詳細來源及正式描述見[職業文件](TALENTS_Veteran.md#veteran_replenish_grenades)。

以下為直接閱讀執行邏輯後的手動狀態推演，未執行 Lua 或遊戲測試。設 frag 類型週期 60 秒，缺額首次被 update 觀察到的時間為 100 秒。

| 邊界案例 | 原始碼推導預期 |
|---|---|
| 首次缺 1 顆，t=100 | 設截止時間 160；本次不補給 |
| t=159.999、t=160 | 均不補給，因使用 `next_grenade_t < t` |
| 首次 update 的 t>160 | 補 1 顆，清除計時；實際時刻取決於 update 排程 |
| t=130 又投出 1 顆 | 缺額變大，但既有截止時間仍為 160 |
| t=140 拾取補滿，之後缺額 | 觀察到滿額便清除進度；新缺額重新計滿週期 |
| 補 1 顆後仍缺額 | 下一次 update 才設定下一個截止時間，不一次補滿、不追補多個逾期週期 |
| 改以 krak 類型首次缺額 t=100 | 截止時間 190；相同嚴格大於規則 |
| 無 grenade ability | 清除 next_grenade_t 與缺額狀態 |

驗收：當前節點、talent、週期設定、更新邏輯、restore 路徑與上限均已直接核對。內部 `name` 的 60 秒及通用 fallback 75 秒不等於所有手雷實際週期。核心靜態機制完成；遊戲內顯示、音效、排程延遲及運行中切換配裝的生命周期未實測。
